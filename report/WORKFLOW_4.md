# Workflow for study 4 (realism of the hybrid generator)

**Question.** Why can a small CNN tell our synthetic ECGs from real ones (detector AUC 1.00), and can we close that gap
by modelling (1) the **non-beat signal** (residual noise + baseline wander) and (2) **beat-to-beat variation in shape**,
without retraining the beat diffusion model and without copying real data? Then: **does more realism make the synthetic
ECGs more useful** to a classifier?

Same layout as `WORKFLOW_2.md` / `WORKFLOW_3.md`: who does what, in which order, and what has to be true before moving on.
The confirmatory part is fixed in `report/PREREGISTRATION_4.md` (drafted in Phase 5, registered before Phase 6).

Status: **plan only** (2026-10-29). Nothing below has been run. Study 3 is building on the GPU.

## What we already know (this changes the pitch)

The study 1 detector ablations (`_beat_ablation.py`, `generator_comparison/scorecard/detector_ablation_*.json`)
rebuilt *real* train ECGs from parts and asked the detector (`realism_detector.py`) to find them:

| variant (real ECG rebuilt from …) | detector AUC |
|---|---|
| A  the real ECG itself (derived leads recomputed) | 0.49 |
| E  own median template + own residual + own wander | 0.51 |
| C  own template + **Gaussian-process residual** + own wander | **1.00** |
| D  own template + own residual + **Gaussian-process wander** | **0.95** |
| G  own template + **another recording's real residual** + own wander | **1.00** |
| K  own template + **own residual shifted in time** (≥ 0.5 s) + own wander | **1.00** |
| T_rand  **another recording's template** at own R-peaks + own residual + own wander | 0.96 |
| T_match  as T_rand, donor with the closest mean RR | 0.95 |
| generated templates + full assembly (the study 2 pool) | 1.00 |

What this means:
1. **The residual is locked to the beats.** A *real* residual is as detectable as our Gaussian process when it is
   shifted (K) or borrowed from another ECG (G). The residual is not "noise between beats". Most of it is each beat's
   deviation from the median template, so it only looks real when it sits *on the right beats, around the right
   template* (T_rand / T_match).
2. **So fixes 1 and 2 are mostly the same problem.** Beat-to-beat shape variation (fix 2) *is* the beat-locked part of
   the residual (fix 1).
3. **Wander is a second, independent giveaway** (D: 0.95 even with a perfect residual). Fix 1 has to cover wander as
   well, or the headline AUC will not move.
4. **Rejected, with evidence:** a "bank" of real residual segments (G, K: AUC 1.00). It would also copy real data,
   which is a privacy problem. It stays out of the plan.

## The decomposition (fixed before anything is built)

For one recording on the 8 independent leads (z-scored, `synthetic_generation/leads.py`):

```
x  =  Σ_k  place( template + d_k , R_k )   +   r   +   w
      └──── beats, each with its own deviation d_k ────┘   leftover  wander (< 0.5 Hz)
```

- **template:** the recording's median beat (as now); generated by the diffusion model in synthetic ECGs.
- **d_k:** beat k's deviation from the template, restricted to a low-rank basis (PCA of real beat deviations, rank chosen
  in Phase 1). It is fitted by least squares jointly over all beats, so overlapping windows (STACH) are handled.
  **Fix 2 models d_k.**
- **r:** what is left after the per-beat fit. **Fix 1 models r and w.**
- No signal is counted twice. The current generator is the special case d_k = 0, with r = the full residual.

Phase 1 must show that this split is sound. A real ECG rebuilt from its own (template, d_k, r, w) is undetectable
(AUC ≈ 0.5, like E). Swapping only r for a model then tells us how much fix 1 matters; swapping only d_k tells us how
much fix 2 matters.

## Ground rules

- **Frozen code, now and permanently:** `synthetic_generation/assembly.py`, `beats.py`, `sample.py`, `utils.py`,
  `leads.py`, `model.py`, `_beat_gen_pool.py`, `realism_detector.py`.
  - Study 3's build launches `_beat_gen_pool.py` subprocesses that import these modules, so editing them would change
    study 3's remaining pools.
  - Studies 1–3 also depend on them for reproducibility.
  - All study 4 code goes in **new** modules: `synthetic_generation/realism/`, plus `_study4_*.py` scripts.
  - `_study3_common.check_frozen` is extended with the hashes of these files and run at every phase.
- **No GPU job until study 3's 180 runs are finished.** The card is 4 GB. Phases 0–3 run on CPU (detector forced to CPU),
  so they can run in parallel with study 3.
- **The test split is not used in development.** Realism uses train data only. Usefulness during development uses the
  validation split. The test split is used at most once, in Phase 6 (see D2).
- **Two detectors, to avoid tuning to one judge.** The train split is divided by patient into:
  - **part A:** fits the noise and deviation models; it is also the real side of the *development* detector.
  - **part B:** the real side of a *judge* detector. The judge has a different architecture and is run only in Phase 6.
  - Every recording used to fit a model is excluded from both real sides (`src_idx`), so memorised noise cannot lower
    the AUC.
- **Tune against physiology, not the detector.** Model strength (deviation variance, envelope shape, wander amplitude)
  is calibrated to real statistics measured in Phase 1. The detector only checks the result.
- Each phase ends with a commit and an **intense audit**. A failed gate is written down, not quietly retried.

```
Phase 0  Literature check + baseline measurements     ~0.5 day   CPU         <- GO / NO-GO on novelty
Phase 1  Diagnose: decomposition, real statistics     ~1 day     CPU
Phase 2  Fix 1 on real templates (residual + wander)  ~1-2 days  CPU (GPU only if escalated)
Phase 3  Fix 2 on real templates (per-beat variation) ~1-2 days  CPU
Phase 4  Port both to generated templates             ~1 day     GPU (after study 3)
Phase 5  Gate + pre-registration                      ~0.5 day   GPU, val only   <- GO / NO-GO
Phase 6  Confirmatory runs (once)                     ~0.5-1 day GPU
Phase 7  Results .md with all statistics and figures  ~0.5 day
```

## Phase 0: literature check and baselines (CPU)

1. **Literature search** on hybrid generators (learned beat morphology + explicit rhythm/noise model; ECGSYN-style
   dynamical models with learned parts; beat-level diffusion/GAN assembled into rhythms; cyclostationary ECG noise
   models). Output: `report/LITERATURE_4.md` with links.
   - **Gate:** if a published method already does "diffusion beats + modelled per-beat variation + learned residual",
     we reframe it as a replication/extension before writing code.
2. **Patient-level A/B split** of train (`_study4_split.py`, seed fixed, 50/50 within class). Commit the indices.
3. **Detector protocol v2** (`synthetic_generation/realism/detect.py`, a new module; it reuses the frozen `Det` class for
   the development detector):
   - 5 seeds; real side from part A minus `src_idx`; CPU.
   - Report AUC with a 95 % CI over seeds, overall and per class.
   - Also report **AUC by input band** (detector retrained on low-pass < 0.5 Hz, 0.5–40 Hz, and on the TP segment only),
     so we see *where* the giveaway is, not just that it exists.
4. **Baselines under protocol v2:** E (≈ 0.5 expected), C, D, the oracle pool and the study 2 generated pool. These are
   the numbers every later phase is compared with.

Exit check: E ≈ 0.5 under the new protocol (if not, the protocol is broken); baselines reproduce the study 1 ablations
within the CIs; A/B split is patient-disjoint.

## Phase 1: diagnose (CPU)

Measured on part A only, per class (`_study4_diagnose.py` → `generator_comparison/study4/diagnostics.json` + figures):

1. **Per-beat decomposition** (`synthetic_generation/realism/decompose.py`):
   - PCA of real beat deviations; choose the rank where rebuilt ECGs stay undetectable (AUC ≤ 0.55).
   - Report explained variance per class.
2. **Where the residual lives:** variance of the residual against beat phase (R − 250 ms … R + 450 ms, then the TP
   segment), real vs the current Gaussian process. *Expected:* real residual variance peaks around the QRS and T wave;
   the Gaussian process is flat.
3. **Beat-to-beat statistics** (calibration targets for fix 2):
   - variance of the deviation coefficients
   - lag-1 correlation across beats
   - coupling to RR interval and to respiration
   - ectopic or outlier-beat rate
4. **Wander statistics** (targets for fix 1):
   - spectrum and amplitude distribution
   - non-stationarity (steps, drifts)
   - correlation with residual scale, and cross-lead structure
   - why D is detectable
5. **Leftover r statistics:** is r after the per-beat fit close to stationary? This decides whether a Gaussian process is
   enough for r.

Exit check: the decomposition rebuilds real ECGs undetectably; there is one figure per question above; the list of
calibration targets is frozen in `diagnostics.json` before Phase 2 starts.

## Phase 2: fix 1 on real templates (CPU)

Semi-synthetic variants in the style of `_beat_ablation.py`: real template at real R-peaks, each candidate replacing
**only** r and/or w. Ladder, cheapest first; stop climbing when the bar is met:

| id | residual r | wander w | why |
|---|---|---|---|
| R0 | own real per-beat deviations + **GP leftover** | own | is a stationary process enough once beat variation is real? |
| R1 | **cyclostationary GP**: stationary GP × beat-phase envelope learned in Phase 1 | own | the cheapest beat-locked noise |
| W1 | own | **new wander model** (non-stationary drift, amplitude from the real distribution, coupled to residual scale) | targets D |
| R1+W1 | R1 | W1 | full fix 1 |
| R2 | **learned leftover generator** (small conditional 1-D diffusion/VAE on R-aligned leftover segments) | W1 | only if R1 misses the bar; GPU, after study 3 |

- Pass bar: development-detector AUC **≤ 0.70** (the bar already stated in `_beat_ablation.py`), with own d_k kept real.
- Each variant also gets the Phase 1 statistics vs real, so we can see *why* it passes or fails.
- **Memorisation check** for any learned model: nearest-neighbour correlation of generated r to the part-A training
  residuals; > 0.98 counts as a copy.

## Phase 3: fix 2 on real templates (CPU)

Replace the real d_k with **modelled** per-beat variation around the recording's own template:

- **V1 (statistical, default):** per-beat PCA coefficients drawn as an AR(1) process across beats, with the per-class
  covariance and lag-1 correlation from Phase 1, plus RR and respiration coupling. Respiration then lives here instead of
  the current fixed amplitude modulation.
- Variants rebuilt with:
  - **V1 + own r + own w:** isolates fix 2.
  - **V1 + best fix 1:** the full model.
  - **d_k = 0 + best fix 1:** isolates fix 1.
  - Together with Phase 2, this gives a **2 × 2 ablation table** (fix 1 on/off × fix 2 on/off). That table is the core
    result of the study.
- Calibration check: the beat-to-beat statistics of V1 must match real (within 10 % on variance and lag-1 correlation)
  **before** the detector is run.

## Phase 4: port to generated templates (GPU, after study 3)

All new code; the frozen sampler is not touched.

- **Default:** apply the statistical V1 deviation model around each *generated* template (no diffusion changes) plus the
  fix 1 noise and wander models. `synthetic_generation/realism/assemble_v2.py`, `_study4_pool.py`.
- **Diffusion-native alternative** (only if V1 fails on generated templates). It needs a new sampler module, because the
  frozen sampler adds fresh noise at every step, so drifting only the starting noise does nothing. Options:
  - (a) a deterministic DDIM sampler, with the start noise drifting between beats as a norm-preserving AR(1);
  - (b) every step's noise AR(1)-correlated across beats;
  - (c) lightly re-noise the template and denoise it once per beat (SDEdit-style), with the strength calibrated to the
    Phase 1 beat-to-beat statistics.
- Build the v2 pool (same counts and seeds scheme as study 2's pools; new seed range), the v1 pool (the current
  generator, rebuilt with the same template draws), and the oracle-v2 pool (real templates + v2 assembly).
- Checks: nonfinite, |z| > 20 rate, class rhythm bounds (HR inside class), scorecard, memorisation of templates and noise.

## Phase 5: gate and pre-registration (val only)

- **G1 (realism moved):** development detector AUC on v2 pool < v1 pool, with non-overlapping seed CIs.
- **G2 (still usable):** train-on-synthetic balanced accuracy on real validation for v2 ≥ v1 − 0.05. Realism must not
  have been bought by losing class information.
- **G3 (no copying):** memorisation checks pass.
- **G4 (determinism):** one augmentation run repeated gives an identical validation history.
- Then write `PREREGISTRATION_4.md` (hypotheses, tests, decision wording, hashes) and register it by commit.

## Phase 6: confirmatory runs (once)

Registered hypotheses (draft; final wording is fixed in Phase 5):

- **H1 (realism, primary):**
  - The *judge* detector (different architecture, real side from part B) gives a lower AUC on v2 than on v1.
  - Unit: judge seed × pool draw. Paired test and bootstrap CI.
  - The judge was never used in development.
- **H2 (usefulness without real data):** train-on-synthetic balanced accuracy on real validation, v2 vs v1.
- **H3 (usefulness as augmentation):** the study 2 recipe (6,250 steps, deterministic) with real + v1 vs real + v2,
  new seeds, macro-F1. Where it is measured is decision D2.
- **Secondary:**
  - the 2 × 2 ablation on the judge detector
  - per-class AUC
  - AUC by input band
  - privacy: nearest-neighbour distance and a membership-inference test against part A
- **The result is reported whichever way it goes.** "Realism improved but usefulness did not" is a legitimate and
  publishable answer, and study 2 already hints that "better-looking" synthetic ECGs do not automatically help more.

## Risks

- **AFIB:** atrial activity (f-waves) lives in the leftover r and is irregular, not beat-locked. It may need its own
  model and is the most likely class to stay detectable.
- **The detector may find a third giveaway** once these two are fixed (for example amplitude scale: typical amplitude is
  ~12 % above real). The by-band AUC in Phase 0 and the 2 × 2 table will show this. It is a result, not a failure.
- **Templates themselves:** T_rand / T_match (0.95–0.96) show that a template that does not match its own residual is
  detectable. With fully modelled d_k and r, this mismatch should disappear, but if it does not, the remaining gap is in
  the diffusion model, which is out of scope here.
- **Overfitting the development detector:** controlled by the judge detector, part B and physiology-based calibration.
